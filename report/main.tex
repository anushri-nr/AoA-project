\begin{abstract}
This report studies two problems, one solved with network flow and one shown
to be NP-complete. The first comes from cloud computing: tasks must be
assigned to compatible servers without exceeding their execution capacity.
We formulate it as capacitated bipartite matching, reduce it to maximum flow
with a reduction that preserves feasibility and objective values in both
directions, and give an end-to-end algorithm that constructs the network,
runs Dinic's algorithm, and extracts an optimal assignment in
$O((n+m+2)^2(n+m+r))$ time and $O(n+m+r)$ space for $n$ tasks, $m$ servers
and $r$ eligible pairs. The second comes from software engineering: a team
wants the smallest subset of a regression test suite that still checks every
requirement. We model it as a set-covering problem, prove its decision
version NP-complete by a polynomial reduction from \VC{}, and give a greedy
algorithm that runs in $O(km + N + n)$ time and returns at most
$H(d) \le \ln d + 1$ times the optimal number of tests. Java implementations
and reproducible benchmarks accompany both parts. The measured running times
are analyzed separately from the theoretical worst-case bounds; for the
greedy algorithm they match the fitted model with $R^2 = 0.992$, and on 630
small instances greedy is optimal 61\% of the time and never worse than
1.43 times the optimum.
\end{abstract}

\section{Introduction}
This report solves two practical problems with two algorithmic tools,
following the same problem-to-algorithm structure for both: the real-world
setting, its abstraction, the reduction and proof, the algorithm, its
complexity, an interpretation in the application domain, a worked example,
and experiments.

Section~\ref{sec:cloud-problem} presents Cloud Task Assignment. Tasks have
compatibility requirements, servers have finite execution slots, and the
objective is to admit as many tasks as possible during one scheduling
interval. We model feasible placements as capacitated bipartite matching,
construct a flow network, and use Dinic's algorithm to obtain an optimal
assignment.

Section~\ref{sec:p2} presents regression test-suite minimization. As a
system evolves, its regression test suite keeps growing, and rerunning all of
it after every change becomes slow. Choosing the fewest tests that still check
every requirement is known in the software-engineering literature as
\emph{test-suite minimization}~\cite{harrold1993,yoo2012}. We show that this
problem is NP-complete, so no polynomial-time algorithm is expected to solve it
exactly, and we give and evaluate a greedy algorithm that solves it well in
practice.

In both parts the experiments characterize measured execution on synthetic
inputs without treating random-input behavior as a proof of the worst-case
bounds. The appendices contain the complete Java implementations and a
disclosure of AI-assisted development.

\section{Problem 1: Maximum Flow---Cloud Task Assignment}
\label{sec:cloud-problem}
\subsection{Introduction}
Cloud computing platforms execute computational tasks on heterogeneous
servers. Software runtimes, processor architectures, accelerators, and
security configurations may restrict the servers eligible to execute a
particular task. Meanwhile, each server has a bounded number of available
task slots. An assignment that ignores compatibility is infeasible, and
an assignment that ignores available slots can overload a server.

For example, a task requiring a GPU can execute only on a compatible
GPU-enabled server, whereas another task may require a particular runtime.
A task that can use several servers should not unnecessarily occupy the
only server eligible for a more restricted task. Independent greedy
decisions can therefore leave avoidable rejections even when capacity is
available elsewhere.

The objective is to admit as many tasks as possible during one scheduling
interval. This is meaningful when tasks have equal admission value: it
minimizes the number of unassigned requests under the modeled restrictions.
It does not directly optimize completion time, fairness, energy, or revenue.
The model applies to admission and placement with preallocated execution
slots rather than to unrestricted multidimensional resource scheduling.

\subsection{Problem Setting and Abstraction}
\subsubsection{Inputs and Assumptions}
Let $T=\{t_1,\ldots,t_n\}$ be the task set and
$S=\{s_1,\ldots,s_m\}$ the server set, with $T\cap S=\varnothing$.
Let $R\subseteq T\times S$ be the eligibility relation, containing each
eligible pair once, and write $r=|R|$. Each server $s_j$ has a capacity
$c_j\in\mathbb{Z}_{\geq0}$.

The model assumes the following:
\begin{enumerate}
\item Eligibility and capacities remain fixed during the scheduling interval.
\item Each task is indivisible, occupies exactly one slot on any eligible
server, and may be assigned to at most one server.
\item Slots on a server are interchangeable. Eligibility and slot capacity
capture all placement constraints.
\item Tasks have equal admission value and introduce no precedence,
communication, affinity, or additional shared-resource constraints.
\item Leaving tasks unassigned is permitted. Servers need not be filled.
\end{enumerate}
In particular, hardware heterogeneity is represented by eligibility and slot
counts. If resource usage depends on task combinations in a way that cannot
be represented by these quantities, the equivalence proved below does not
apply to that richer problem.

\subsubsection{Integer Programming Formulation}
Define $a_{ij}=1$ if $(t_i,s_j)\in R$ and $a_{ij}=0$ otherwise. Let
$x_{ij}=1$ exactly when $t_i$ is assigned to $s_j$. The optimization problem is
\begin{align}
\max\quad & \sum_{i=1}^{n}\sum_{j=1}^{m}x_{ij} \label{eq:objective}\\
\text{subject to}\quad
&\sum_{j=1}^{m}x_{ij}\leq1 &&\forall i, \label{eq:task}\\
&\sum_{i=1}^{n}x_{ij}\leq c_j &&\forall j, \label{eq:server}\\
&x_{ij}\leq a_{ij} &&\forall i,j, \label{eq:eligible}\\
&x_{ij}\in\{0,1\} &&\forall i,j. \label{eq:binary}
\end{align}
The output is the selected task--server pairs, the unassigned tasks, and the
maximum number of assigned tasks. Constraint~\eqref{eq:task} enforces task
uniqueness, \eqref{eq:server} enforces server capacity, and
\eqref{eq:eligible} prohibits ineligible placements.

Every feasible real-world assignment gives a feasible binary vector by
marking its selected pairs. Conversely, every feasible binary vector defines
a permitted placement by selecting the entries equal to one. These mappings
are inverses under the stated assumptions, and
\eqref{eq:objective} equals the number of assigned tasks.

\subsubsection{Capacitated Bipartite Matching}
The graph $G=(T\cup S,R)$ is bipartite. For a selected edge set $M\subseteq R$,
feasibility is equivalent to
\begin{equation}
\deg_M(t_i)\leq1,\qquad \deg_M(s_j)\leq c_j.
\end{equation}
The objective is to maximize $|M|$. Thus, the abstraction is maximum-cardinality
bipartite $b$-matching with $b(t_i)=1$ and $b(s_j)=c_j$~\cite{ahuja1993}.
It reduces to ordinary bipartite matching when all server capacities equal one.

\subsection{Reduction to Maximum Flow}
\subsubsection{Network Definition}
Introduce new, distinct source and sink vertices $a$ and $b$. Construct
$N=(V,E,u,a,b)$ with
\begin{equation}
V=\{a,b\}\cup T\cup S
\end{equation}
and
\begin{align}
E={}&\{(a,t_i):t_i\in T\}\nonumber\\
 &\cup\{(t_i,s_j):(t_i,s_j)\in R\}\nonumber\\
 &\cup\{(s_j,b):s_j\in S\}.
\end{align}
The capacity function $u:E\to\mathbb{Z}_{\geq0}$ is
\begin{equation}
u(e)=\begin{cases}
1,&e=(a,t_i),\\
1,&e=(t_i,s_j),\ (t_i,s_j)\in R,\\
c_j,&e=(s_j,b).
\end{cases}
\end{equation}
Zero-capacity server-to-sink edges are retained. Hence the exact original
network sizes are
\begin{equation}
|V|=n+m+2,\qquad |E|=n+m+r.
\label{eq:size}
\end{equation}

\subsubsection{Reduction Algorithm and Encoding Size}
\leavevmode\par
\begin{lstlisting}[caption={Reduction: network construction only.},label={lst:reduce}]
BUILD-NETWORK(T, S, R, c):
  create distinct source a and sink b
  create one vertex per task and server
  initialize empty adjacency lists
  references = empty list
  for each task t_i:
    ADD-EDGE(a, t_i, 1)
  for each (t_i, s_j) in R:
    edge = ADD-EDGE(t_i, s_j, 1)
    append (i, j, edge) to references
  for each server s_j:
    ADD-EDGE(s_j, b, c_j)
  return (network, references, a, b)
\end{lstlisting}

With explicit task, server, and eligibility lists, construction uses
$O(n+m+r)$ graph operations. An eligibility matrix instead requires
$O(nm)$ scanning time. If $\ell(c_j)$ is the binary encoding length of $c_j$,
the output encoding requires
\begin{equation}
O\!\left((n+m+r)\log(n+m+2)+\sum_j\ell(c_j)\right)
\end{equation}
bits under a conventional explicit graph encoding. Each capacity is copied
once. No step creates $c_j$ vertices or edges, so large capacities do not
cause a pseudopolynomial expansion.

The reduction constructs an instance; it does not compute a maximum flow.
For the decision version, an assignment threshold $k$ is preserved: the
question becomes whether the constructed network admits flow of value at
least $k$.

\subsection{Proof of Correctness}
A feasible flow satisfies $0\leq f(e)\leq u(e)$ and conservation at all
vertices except $a$ and $b$. Its value is
$|f|=\sum_i f(a,t_i)$ because $a$ has no incoming original edges.

\begin{lemma}[Assignment to flow]
Every feasible assignment of $k$ tasks induces a feasible integral flow of
value $k$ in $N$.
\end{lemma}
\begin{proof}
Let $M\subseteq R$ be a feasible assignment with $|M|=k$. Set
$f(t_i,s_j)=1$ for pairs in $M$ and zero for other eligible pairs. Define
\begin{align}
f(a,t_i)&=\sum_{j:(t_i,s_j)\in R}f(t_i,s_j),\\
f(s_j,b)&=\sum_{i:(t_i,s_j)\in R}f(t_i,s_j).
\end{align}
Task uniqueness bounds each $f(a,t_i)$ by one. Eligible middle edges carry
zero or one, and no ineligible edge is used because $M\subseteq R$.
Server feasibility bounds $f(s_j,b)$ by $c_j$. All flows are nonnegative.
The two definitions establish conservation at each task and server vertex.
Thus $f$ is feasible and integral, and
\begin{equation}
|f|=\sum_i f(a,t_i)=\sum_{(t_i,s_j)\in R}f(t_i,s_j)=k.
\end{equation}
\end{proof}

\begin{lemma}[Integral flow to assignment]
Every integral feasible flow of value $k$ induces a feasible assignment of
exactly $k$ distinct tasks.
\end{lemma}
\begin{proof}
Set $M_f=\{(t_i,s_j)\in R:f(t_i,s_j)=1\}$. Each middle edge has capacity
one, so integrality implies its flow is either zero or one. Every selected
pair is eligible by construction. Conservation and source-edge capacity give
\begin{equation}
\deg_{M_f}(t_i)=\sum_j f(t_i,s_j)=f(a,t_i)\leq1,
\end{equation}
where the sum ranges over eligible neighbors. Similarly,
\begin{equation}
\deg_{M_f}(s_j)=\sum_i f(t_i,s_j)=f(s_j,b)\leq c_j.
\end{equation}
Therefore tasks are unique and server capacities are respected. Finally,
\begin{equation}
|M_f|=\sum_{(t_i,s_j)\in R}f(t_i,s_j)=\sum_i f(a,t_i)=k.
\end{equation}
Because no task appears twice, these edges assign exactly $k$ distinct tasks.
\end{proof}

\begin{theorem}[Equality of optimal values]
The maximum feasible assignment cardinality equals the maximum $a$--$b$
flow value in $N$.
\end{theorem}
\begin{proof}
The first lemma implies $\OPT_{\mathrm{CTA}}\leq\OPT_{\mathrm{MF}}$.
All capacities are integers, so the integral maximum-flow theorem guarantees
the existence of an integral maximum flow~\cite{ahuja1993}. Applying the second lemma to
that flow gives $\OPT_{\mathrm{MF}}\leq\OPT_{\mathrm{CTA}}$. Together,
\begin{equation}
\boxed{\OPT_{\mathrm{CTA}}=\OPT_{\mathrm{MF}}.}
\end{equation}
Integrality asserts the existence of an integral optimum, not that every
feasible or maximum flow is integral. Dinic's algorithm with integer
capacities produces the integral optimum needed for extraction.
\end{proof}

The polynomial construction and objective-preserving mappings establish a
polynomial-time reduction from Cloud Task Assignment to Maximum Flow.

\subsection{Complete Dinic-Based Algorithm}
The algorithm uses Dinic's layered residual-network approach~\cite{dinic1970}.
\subsubsection{Residual Representation}
For each original edge, store a forward residual record and a paired reverse
record. Each record contains its destination, residual capacity, and a link
to its reverse. Initially, residual capacities are the original capacity
and zero, respectively. Augmenting on a reverse edge cancels previously
sent original-edge flow. The residual representation stores $2|E|$ records.

\begin{lstlisting}[caption={Paired residual-edge insertion.}]
ADD-EDGE(u, v, capacity):
  forward = new Edge(v, capacity)
  reverse = new Edge(u, 0)
  forward.reverse = reverse
  reverse.reverse = forward
  append forward to adj[u]
  append reverse to adj[v]
  return forward
\end{lstlisting}

\subsubsection{Level Graph and Blocking Flow}
\leavevmode\par
\begin{lstlisting}[caption={Breadth-first search of the residual graph.}]
BUILD-LEVELS(a, b):
  level[v] = -1 for every vertex v
  level[a] = 0
  Q = queue containing a
  while Q is not empty:
    u = remove front of Q
    for e in adj[u]:
      if e.residual > 0 and level[e.to] == -1:
        level[e.to] = level[u] + 1
        append e.to to Q
  return level[b] != -1
\end{lstlisting}

The following explicit-stack DFS matches the Java implementation. Array
$P[0..d]$ stores the current vertex path, $H[0..d-1]$ its residual edges,
and $B[d]$ the path bottleneck. The current-edge pointer $q[u]$ persists
throughout a phase and advances past edges that cannot contribute further
flow in that phase.

\begin{lstlisting}[caption={Iterative DFS augmentation in one level graph.}]
SEND-FLOW(a, b, limit):
  d = 0
  P[0] = a
  B[0] = limit
  while true:
    u = P[d]
    if u == b:
      amount = B[d]
      for h = 0 to d-1:
        H[h].residual -= amount
        H[h].reverse.residual += amount
      return amount

    while q[u] < length(adj[u]):
      e = adj[u][q[u]]
      if e.residual > 0 and
          level[e.to] == level[u] + 1:
        break
      q[u] += 1

    if q[u] == length(adj[u]):
      if d == 0:
        return 0
      d -= 1
      q[P[d]] += 1
    else:
      e = adj[u][q[u]]
      H[d] = e
      P[d+1] = e.to
      B[d+1] = min(B[d], e.residual)
      d += 1
\end{lstlisting}

\begin{lstlisting}[caption={Dinic maximum flow.}]
DINIC(a, b, n):
  value = 0
  while BUILD-LEVELS(a, b):
    q[v] = 0 for every vertex v
    while true:
      pushed = SEND-FLOW(a, b, n)
      if pushed == 0:
        break
      value += pushed
  return value
\end{lstlisting}
The limit $n$ is sufficient because total source capacity is $n$. If
$n=0$, the initial BFS cannot reach the sink and no DFS is called.

\subsubsection{Assignment Extraction and Overall Procedure}
References to the original middle edges are retained during construction.
Each has capacity one, so its flow equals one minus its final forward
residual capacity.

\begin{lstlisting}[caption={Complete assignment algorithm.}]
CLOUD-TASK-ASSIGNMENT(T, S, R, c):
  (network, references, a, b) =
      BUILD-NETWORK(T, S, R, c)
  value = DINIC(a, b, |T|)
  assignment[i] = UNASSIGNED for every task i
  count = 0
  for (i, j, edge) in references:
    if edge.residual == 0:
      assert assignment[i] == UNASSIGNED
      assignment[i] = j
      count += 1
  assert count == value
  return (value, assignment)
\end{lstlisting}

\subsubsection{Termination and Algorithmic Correctness}
\begin{theorem}
The complete algorithm terminates and returns a maximum-cardinality feasible
task assignment.
\end{theorem}
\begin{proof}
The initial zero flow is feasible and integral. Every successful DFS
augmentation follows a residual source-to-sink path and is bounded by its
bottleneck. Paired residual updates preserve edge-capacity constraints and
flow conservation; integer bottlenecks preserve integrality.

During a phase, DFS follows edges whose levels increase by one, so the
explicit stack cannot contain a cycle and has depth at most $|V|-1$.
Within one DFS call, $B[d]$ is the minimum residual capacity of the current
path prefix. Backtracking advances the parent's current-edge pointer;
restarting after an augmentation reconstructs the path and its bottlenecks.

Augmentation creates reverse residual capacity only toward lower levels.
Consequently, no new admissible edges are created in the current phase.
An exhausted edge or vertex need not be revisited, and an admissible edge
that becomes saturated remains saturated for that phase. Each successful
augmentation saturates at least one admissible edge. Thus repeated DFS
calls terminate with a blocking flow.

After a blocking flow, any remaining residual source-to-sink path has
strictly greater shortest-path length. There are fewer than $|V|$
successful phases, so Dinic terminates. At termination there is no residual
source-to-sink path; therefore its feasible flow is maximum by the
max-flow/min-cut characterization~\cite{ford1956}. The integral
flow-to-assignment lemma proves that extraction yields a feasible assignment
of the same value. The equality-of-optima theorem proves optimality.
\end{proof}

\subsection{Running Time and Space Analysis}
With adjacency-list input, construction costs $O(n+m+r)$ and extraction costs
$O(n+r)$. Write $V=|V|$ and $E=|E|$ in the following bounds. BFS costs
$O(V+E)$ per phase. Current-edge pointers advance across at most $O(E)$
records per phase. There are at most $O(E)$ successful augmentations in a
phase, each traversing $O(V)$ edges, giving the general $O(VE)$ blocking-flow
bound. Fewer than $V$ successful phases give Dinic's general $O(V^2E)$
bound~\cite{dinic1970,ahuja1993}.

Using~\eqref{eq:size}, the overall assignment time is
\begin{align}
&O(n+m+r)+O((n+m+2)^2(n+m+r))\nonumber\\
&\hspace{3em}+O(n+r)
=O((n+m+2)^2(n+m+r)).
\end{align}
The network, extraction references, level and current-edge arrays, queue,
explicit path stack, and output require $O(V+E)=O(n+m+r)$ machine words.
When $n=m=0$, the algorithm uses constant time and space. When only one
set is empty, the implementation still incurs construction costs
proportional to the input representation.

These are standard unit-cost graph-operation bounds. Binary-encoded
arbitrary-precision capacities add arithmetic costs polynomial in their bit
lengths. The Java implementation uses \texttt{long} residual values and
\texttt{int} vertex indices and capacities; inputs must fit those supported
representations and available memory. Synthetic generation scans all
$nm$ potential eligibility pairs and is outside the timed assignment
algorithm. The general Dinic bound is a valid upper bound; no tightness
claim for this restricted family is made.

\subsection{Explanation in the Language of the Problem Domain}
In the cloud platform, a unit of flow represents one admitted task.
A source-to-task edge permits admission at most once. Eligibility edges
list the servers that can execute that task, and a server-to-sink edge
limits its total admitted workload. Dinic's residual edges represent
reconsidering an earlier placement: a flexible task can be moved to an
alternative compatible server so a more restricted task can use the
released slot. Such a reassignment does not split or duplicate a task.
When no residual admission path remains, the maximum-flow theorem
certifies that no feasible placement can admit more tasks under the
modeled constraints. Unassigned tasks must wait for a later interval
or a change in available capacity or eligibility.

\subsection{Worked Example and Execution Trace}
Consider five tasks, three servers, and capacities $(c_1,c_2,c_3)=(1,2,2)$.
The eligibility matrix is
\begin{equation}
A=\begin{array}{c|ccc}
 &s_1&s_2&s_3\\\hline
t_1&1&1&0\\
t_2&1&0&0\\
t_3&0&1&1\\
t_4&0&1&0\\
t_5&0&0&1
\end{array}.
\end{equation}
The network has ten vertices and fifteen original edges: five source edges,
seven eligibility edges, and three sink edges. Source and eligibility
edges have capacity one; sink edges have capacities one, two, and two.

With task and server indices examined in increasing order, the first BFS
finds task vertices at level one, servers at level two, and the sink at
level three. The first blocking flow sends one unit along each path
\begin{align*}
&a\to t_1\to s_1\to b,\quad a\to t_3\to s_2\to b,\\
&a\to t_4\to s_2\to b,\quad a\to t_5\to s_3\to b.
\end{align*}
The flow value is four. Task $t_2$ cannot yet use $s_1$ because its sink
edge is saturated. In the next phase, BFS finds a residual path with
vertex levels $0,1,2,3,4,5,6,7$:
\begin{equation}
a\to t_2\to s_1\to t_1\to s_2\to t_3\to s_3\to b.
\end{equation}
The edges $s_1\to t_1$ and $s_2\to t_3$ are reverse residual edges. Sending
one unit cancels two earlier placements and replaces them with a reassignment
that increases total flow to five. Extraction gives
\begin{equation}
X^*=\begin{array}{c|ccc}
 &s_1&s_2&s_3\\\hline
t_1&0&1&0\\
t_2&1&0&0\\
t_3&0&0&1\\
t_4&0&1&0\\
t_5&0&0&1
\end{array}.
\end{equation}
All source edges carry one unit, and sink edges carry $(1,2,2)$. The cut
containing only $a$ has capacity five. The feasible flow reaches this cut
capacity, certifying optimality independently of the task-count upper bound.

\subsection{Implementation and Verification}
The accompanying Java 17 implementation stores adjacency lists, reverse-edge
indices, integer residual capacities, BFS arrays, and an explicit DFS path
stack. The complete Java source is reproduced in
Appendix~\ref{app:java-source}. Every measured repetition constructs a fresh
network. Assignment extraction initializes an array to $-1$ for unassigned tasks and selects
eligible edges carrying one unit of flow. Validation checks eligibility,
server loads, and agreement between assigned-task count and returned flow.

The supplied self-test checks the worked example and compares the algorithm
with an exhaustive assignment optimizer on 672 tiny generated instances,
including empty dimensions and zero-capacity cases. These are implementation
checks rather than a substitute for the proof. The published CSVs contain
maximum-flow values and timings; the benchmark currently consumes assignments
internally rather than exporting them. A reusable custom-instance solver
interface returning both the flow value and assignment array is a useful
extension of the benchmark entry point.

For additional optimality verification, residual reachability can identify
the source side of a minimum cut after termination. If that side contains
task subset $X$ and server subset $Y$, its original capacity is
\begin{equation}
n-|X|+|R\cap(X\times(S\setminus Y))|+\sum_{s_j\in Y}c_j.
\end{equation}
A feasible assignment whose cardinality equals this capacity is certified
optimal. This certificate is distinct from feasibility validation alone.

\subsubsection{Construction and Maximum-Flow Costs}
Figure~\ref{fig:components} separates network construction from maximum-flow
computation. At $n=1000$, $m=100$, and fixed capacities, construction increases
from 0.0250~ms at $p=0.01$ to 0.8224~ms at $p=0.5$; the corresponding
Dinic times are 0.0606~ms and 0.5120~ms. Thus, maximum-flow computation
dominates the component medians in this sparse setting, whereas construction
is larger in the dense setting. Across all 1,458 measured repetitions, the
median within-run construction, Dinic, and extraction fractions are 51.0\%,
47.0\%, and 1.8\%, respectively. These separately computed median fractions
need not sum to 100\%.

Construction is therefore a material cost in the observed implementation.
Forward/reverse edge objects and adjacency-list storage provide plausible
sources of allocation and memory-access overhead. Garbage collection, cache
behavior, and JVM compilation may also affect timings. The CSV files contain
no allocation, collection, cache, or phase-count counters, so these explanations
remain hypotheses rather than measured causal findings. An implementation
using compact edge arrays would require a separate controlled evaluation.

\subsubsection{Comparison with the Worst-Case Upper Bound}
The constructed network contains
\begin{equation}
V=n+m+2,\qquad E=n+m+r.
\end{equation}
Construction and extraction require $O(n+m+r)$ and $O(n+r)$ time,
respectively. Using Dinic's general $O(V^2E)$ bound, the complete algorithm
has worst-case upper bound
\begin{equation}
O\!\left((n+m+2)^2(n+m+r)\right),
\end{equation}
with $O(n+m+r)$ space. This is an upper bound rather than a tight runtime
prediction for the tested layered networks. In particular, $V^2E$ is an
operation-count expression without a calibrated conversion to elapsed time.

For the controlled slice $m=100$, $p=0.1$, and fixed capacities, median
$V^2E$ increases by factors of 41.04 and 274.19 as $n$ increases from
100 to 500 and 1,000. The corresponding measured total-time factors are
6.23 and 13.12, and Dinic-time factors are 10.22 and 22.06
(Fig.~\ref{fig:growth}). Observed growth is therefore much smaller than the
growth of this general worst-case expression over the measured range.
This is compatible with the upper bound: random instances need not require
the worst-case number of blocking-flow phases or edge traversals. Additionally,
fixed aggregate capacity caps flow at 400 in this slice even as the number
of tasks increases. The data do not establish which mechanism dominates.
No theoretical timing curve or synthetic timing observations are introduced.

\subsubsection{Limitations and Validity}
The results describe small synthetic instances, one JVM process, three input
seeds, three density values, and two server counts. Five warm-up executions
do not establish that JIT compilation stabilized. The distinction between
warm-up, steady-state measurement, and independent JVM invocations is
important in Java performance evaluation~\cite{georges2007}. Several intervals are only
a few microseconds long and may be sensitive to timer overhead, scheduling,
allocation, and background activity. CPU model, RAM, GC events, and per-phase
algorithm counters are not recorded. The measurements therefore do not
support hardware-independent performance claims, a statistical model of
process-level variability, or causal attribution of outliers.

The seed ranges describe variability among three generated inputs, and repeated
executions of the same input are not independent graph samples. Random case
ordering reduces systematic ordering effects but does not eliminate JVM or
machine-state effects. The eligibility model also omits correlated compatibility
requirements, task priorities, and heterogeneous resource consumption.
Additional independent JVM forks, longer warm-up checks, larger parameter
sweeps, and structured or adversarial instances would strengthen subsequent
evaluation. These random-input measurements neither prove the theoretical
worst-case bound nor establish a matching lower bound.

\section{Problem 2: NP-Completeness---Regression Test-Suite Minimization}
\label{sec:p2}

\subsection{Introduction}
\label{sec:p2-intro}
Software teams keep a \emph{regression test suite}: a collection of automated
tests that is rerun after every change to make sure that existing behavior
still works. Each test checks some of the system's \emph{testing
requirements}, such as functional requirements, statements or branches of the
code, or data-flow relationships~\cite{harrold1993}. As the software evolves,
new tests are added for new features and bug fixes, but old ones are rarely
removed. Many tests end up redundant, because other tests already check
everything they check, and running the whole suite after every commit wastes
time and computing resources.

\emph{Test-suite minimization} asks for the smallest subset of the suite that
still checks every requirement that the full suite checks. It is one of the
three main branches of regression-testing research, alongside test selection
and test prioritization~\cite{yoo2012}. Harrold, Gupta and Soffa introduced a
widely used heuristic for it~\cite{harrold1993}, and the problem is commonly
noted to be NP-complete~\cite{yoo2012}. In this section we prove
that claim from first principles and give a greedy algorithm.

\subsection{Problem Setting and Abstraction}
Number the requirements $1,\dots,n$ and the tests $1,\dots,m$. Test $i$ is
described only by the set of requirements it checks.

\begin{definition}[\TSM{}]
An instance consists of a finite universe $U = \{1,\dots,n\}$ of requirements
and a family $\mathcal{S} = (S_1,\dots,S_m)$ of subsets $S_i \subseteq U$,
where $S_i$ is the set of requirements checked by test $i$. A set of tests
$T \subseteq \{1,\dots,m\}$ is a \emph{covering suite} if
$\bigcup_{i\in T} S_i = U$.
\begin{itemize}
  \item \emph{Optimization version:} find a covering suite of minimum size $|T|$.
  \item \emph{Decision version} \TSM{}: given also an integer $k$, decide
        whether a covering suite with $|T| \le k$ exists.
\end{itemize}
\end{definition}

We assume without loss of generality that every requirement is checked by at
least one test (the instance is \emph{feasible}); a requirement that no test
checks can be detected in linear time and reported. We write
$N = \sum_{i=1}^{m} |S_i|$ for the total size of the input, and
$d = \max_i |S_i|$ for the largest number of requirements a single test checks.

This abstraction is exactly the input used by practical minimization tools,
which only need the association between each requirement and the tests that
satisfy it~\cite{harrold1993}. It is also a bipartite graph between tests and
requirements, with an edge whenever a test checks a requirement; $N$ is its
number of edges.

\subsection{Reduction from Vertex Cover}
To show that \TSM{} is NP-complete we prove two things: that it is NP-hard,
by reducing a known NP-complete problem to it, and that it is in NP. We
reduce from \VC{}, one of Karp's original NP-complete
problems~\cite{karp1972}.

\begin{definition}[\VC{}]
A \emph{vertex cover} of an undirected graph $G=(V,E)$ is a set of vertices
$C \subseteq V$ that contains at least one endpoint of every edge. Given $G$
and an integer $k$, \VC{} asks whether $G$ has a vertex cover with
$|C| \le k$.
\end{definition}

\subsubsection{Construction}
Let $(G, k)$ be an instance of \VC{} with vertices $V = \{v_1,\dots,v_p\}$ and
edges $E = \{e_1,\dots,e_q\}$. We build an instance $f(G,k)$ of \TSM{}:
\begin{itemize}
  \item one requirement $j$ for every edge $e_j$, so $U = \{1,\dots,q\}$;
  \item one test $i$ for every vertex $v_i$, which checks exactly the
        requirements of the edges incident to $v_i$:
        $S_i = \{\, j : v_i \in e_j \,\}$;
  \item the same budget $k$.
\end{itemize}
In software terms, think of each edge as a requirement that exactly two tests
check, namely the tests of its two endpoints.
The instance has $n = q$ requirements, $m = p$ tests and total size
$N = \sum_i |S_i| = \sum_i \deg(v_i) = 2q$. It is built with one pass over the
edge list, in $O(p + q)$ time, so the reduction is polynomial.
Fig.~\ref{fig:reduction} shows an example; our implementation is
\texttt{VertexCoverReduction} in Appendix~\ref{app:code}.

\subsection{Proof of Correctness}
\begin{lemma}\label{lem:subset}
A set of vertices $C$ is a vertex cover of $G$ if and only if the
corresponding tests $T_C = \{\, i : v_i \in C \,\}$ check every requirement.
\end{lemma}
\begin{proof}
By the construction, test $i$ checks requirement $j$ exactly when vertex
$v_i$ is an endpoint of edge $e_j$. So requirement $j$ is checked by a test
in $T_C$ exactly when edge $e_j$ has an endpoint in $C$. This holds for every
$j$ at once, so all requirements are checked if and only if all edges are
covered.
\end{proof}

\begin{theorem}\label{thm:reduction}
$G$ has a vertex cover of size at most $k$ if and only if $f(G,k)$ has a
covering suite of size at most $k$. Hence $\VC{} \le_p \TSM{}$.
\end{theorem}
\begin{proof}
Each test corresponds to exactly one vertex, so a set of $k$ tests is the
same as a set of $k$ vertices. By Lemma~\ref{lem:subset}, one is a covering
suite exactly when the other is a vertex cover. The construction takes
polynomial time, so this is a polynomial-time reduction.
\end{proof}

It remains to show that a proposed answer can be checked quickly.

\begin{lemma}\label{lem:np}
\TSM{} is in NP.
\end{lemma}
\begin{proof}
Given a proposed list of tests $T$, we can check in polynomial time that
$|T| \le k$ and that every requirement is checked by some test in $T$: go
through the tests in $T$, mark the requirements they check, and see whether
all $n$ are marked. This takes $O(m + n + N)$ time
(\texttt{CoverageVerifier} in Appendix~\ref{app:code}).
\end{proof}

\begin{corollary}\label{cor:npc}
\TSM{} is NP-complete, and finding a smallest covering suite is NP-hard.
\end{corollary}
\begin{proof}
\VC{} is NP-complete~\cite{karp1972}, so Theorem~\ref{thm:reduction} makes
\TSM{} NP-hard, and Lemma~\ref{lem:np} puts it in NP. A fast algorithm for
the smallest suite would also answer the decision question (compare its size
with $k$), so that problem is NP-hard too.
\end{proof}

The reduction produces instances in which every requirement is checked by
exactly two tests, so the problem stays NP-hard even in that restricted case.

\begin{remark}[Reduction in the other direction]
The assignment asks for a reduction between the abstract problem and a known
NP-complete problem. Note the direction: Theorem~\ref{thm:reduction}
(known problem $\le_p$ our problem) is what proves hardness. The opposite
direction also holds trivially: an instance $(U,\mathcal{S},k)$ of \TSM{} is
literally an instance of \SC{}~\cite{karp1972}, with the same answer, so
$\TSM{} \le_p \SC{}$ by the identity map. Since \SC{} is in NP, this gives a
second proof of Lemma~\ref{lem:np}, and shows the two problems are
polynomially equivalent. On its own, however, a reduction from our problem to
a hard problem would not prove that our problem is hard.
\end{remark}

\subsection{Greedy Algorithm}
Because an exact polynomial-time algorithm is unlikely, we use the greedy rule
that the regression-testing literature also starts from~\cite{yoo2012}:
\emph{repeatedly run the test that checks the most requirements not yet
checked}, until every requirement is checked. Algorithm~\ref{alg:greedy}
implements this rule efficiently. It keeps, for each test $i$, a counter
$g[i]$ (the \emph{gain}) equal to the number of still-unchecked requirements in
$S_i$, and an inverted index $\mathit{byReq}[r]$ listing the tests that check
requirement $r$. When a requirement becomes checked, only the tests that
contain it lose gain, so the counters can be kept up to date cheaply.

\begin{algorithm}[t]
\caption{\textsc{GreedyMinimize}$(U, S_1,\dots,S_m)$}
\label{alg:greedy}
\begin{algorithmic}[1]
\For{$r \gets 1$ \textbf{to} $n$} $\mathit{byReq}[r] \gets$ empty list
\EndFor
\For{$i \gets 1$ \textbf{to} $m$}
  \State $g[i] \gets |S_i|$
  \For{each $r \in S_i$} append $i$ to $\mathit{byReq}[r]$
  \EndFor
\EndFor
\State $\mathit{checked}[1..n] \gets \textbf{false}$;\; $\mathit{left} \gets n$;\; $T \gets \emptyset$
\While{$\mathit{left} > 0$}
  \State $b \gets \arg\max_{i} g[i]$ \Comment{ties: smallest index}
  \If{$g[b] = 0$} \Return ``infeasible'' \EndIf
  \State $T \gets T \cup \{b\}$
  \For{each $r \in S_b$ with $\neg\mathit{checked}[r]$}
    \State $\mathit{checked}[r] \gets \textbf{true}$;\; $\mathit{left} \gets \mathit{left} - 1$
    \For{each $i \in \mathit{byReq}[r]$} $g[i] \gets g[i] - 1$
    \EndFor
  \EndFor
\EndWhile
\State \Return $T$
\end{algorithmic}
\end{algorithm}

\paragraph*{Correctness}
The algorithm maintains the invariant
$g[i] = |\{\, r \in S_i : \neg\mathit{checked}[r] \,\}|$ for every test $i$.
It holds after initialization, when nothing is checked. Each requirement $r$
is marked checked exactly once, and at that moment every test containing $r$,
and only those, has its gain decreased by one, which restores the invariant.

\begin{lemma}\label{lem:greedy-valid}
If every requirement is checked by some test, Algorithm~\ref{alg:greedy}
returns a covering suite after at most $\min(m, n)$ iterations.
\end{lemma}
\begin{proof}
While some requirement is unchecked, a test containing it has gain at least
1, so the chosen test checks at least one new requirement. Hence each
iteration checks a new requirement (at most $n$ iterations), and a chosen test
has gain 0 afterwards, so it is never chosen twice (at most $m$ iterations).
The loop stops only when every requirement is checked. If some requirement is
in no test, all gains eventually reach 0 and the algorithm reports
``infeasible''.
\end{proof}

\paragraph*{Quality guarantee}
Greedy is not always optimal (an example follows in
Section~\ref{sec:p2-example}), but it is never far off.

\begin{theorem}[\cite{chvatal1979}]\label{thm:approx}
Greedy returns at most $H(d)\cdot\mathrm{OPT}$ tests, where $\mathrm{OPT}$ is
the size of a smallest covering suite and
$H(d) = 1 + \tfrac12 + \dots + \tfrac1d \le \ln d + 1$.
\end{theorem}
\begin{proof}[Proof sketch]
Each time greedy picks a test that checks $c$ new requirements, give each of
them a cost of $1/c$. Every pick hands out a total cost of 1, so the total
cost equals the number of tests greedy picks. Now take any test $S$ of an
optimal suite. When the $t$-th last of its requirements is checked, $S$
itself would still check at least $t$ new ones, so greedy's pick checks at
least $t$ and that requirement costs at most $1/t$. The requirements of $S$
therefore cost at most $1 + \tfrac12 + \dots + \tfrac1d = H(d)$ in total.
Every requirement is in some test of the optimal suite, so the total cost,
and hence greedy's number of tests, is at most $H(d)\cdot\mathrm{OPT}$.
\end{proof}

\subsection{Running Time and Space Analysis}
Let $k = |T|$ be the number of tests greedy selects; by
Lemma~\ref{lem:greedy-valid}, $k \le \min(m,n)$.
\begin{itemize}
  \item Building the gains and the inverted index (lines 1--6) touches every
        pair $(i, r)$ with $r \in S_i$ once: $O(m + n + N)$.
  \item Each iteration finds $\arg\max_i g[i]$ by scanning all $m$ counters:
        $O(km)$ over the whole run.
  \item Each requirement is marked checked once, and at that moment the
        algorithm walks its list $\mathit{byReq}[r]$. The lists have total
        length $N$, so all the gain updates together cost $O(N)$. Scanning
        $S_b$ for each chosen test is also $O(N)$ in total, since each test is
        chosen at most once.
\end{itemize}
Hence
\[
T_{\text{greedy}}(m,n,N) = O(km + N + n).
\]
In the worst case $k = \min(m,n)$ and $N \le mn$, giving $O(mn)$, which is
linear in the size of the test-by-requirement matrix. Memory is $O(m + n + N)$.
A priority queue would replace the $O(km)$ scan with $O(N \log m)$ heap
updates; we use the scan because it is simpler and, as the experiments show, it
is very fast in practice.

\subsection{Explanation in the Language of the Problem Domain}
\label{sec:p2-domain}
Start with nothing selected. Look at every test and count how many
requirements it would check that no selected test checks yet; run the test
with the highest count, and repeat until every requirement is checked. A test
whose requirements are all already checked by selected tests has count zero
and is never selected, which is exactly how redundant tests are dropped.

Minimizing only preserves the requirements that are modeled. A removed test
may still have been able to reveal faults that the remaining tests miss, and
studies have found that fault-detection ability can drop noticeably in
practice~\cite{rothermel1998}. A team can limit this risk by
minimizing with fine-grained requirements, or by keeping the full suite for
nightly runs and using the minimized one after each commit.

\subsection{Worked Example and Execution Trace}
\label{sec:p2-example}
Consider a web shop with six requirements: login ($r_1$), logout ($r_2$),
password reset ($r_3$), checkout ($r_4$), refund ($r_5$) and invoice ($r_6$).
The suite has three tests: an \emph{authentication} test
$S_1=\{r_1,r_2,r_3\}$, a \emph{payments} test $S_2=\{r_4,r_5,r_6\}$, and a
long end-to-end \emph{smoke} test $S_3=\{r_2,r_3,r_5,r_6\}$.

Initially the gains are $(g_1,g_2,g_3)=(3,3,4)$, so greedy selects the smoke
test, which checks $r_2,r_3,r_5,r_6$. Each of these requirements lowers the
gain of the other test that contains it, leaving $(1,1,0)$. Greedy then
selects the authentication test for $r_1$ (a tie, broken by the smaller
index), and finally the payments test for $r_4$. It returns three tests,
$\{S_3,S_1,S_2\}$, while the optimum is two, $\{S_1,S_2\}$. The ratio $3/2$
is within the guarantee of Theorem~\ref{thm:approx}, since
$H(4)\approx 2.08$ here.

\subsection{Implementation and Verification}
We implemented the abstraction, the verifier, the reduction, the greedy
algorithm and an exact branch-and-bound solver in Java
(Appendix~\ref{app:code}). Twenty-six unit tests pass. One checks
Lemma~\ref{lem:subset} exhaustively: on 200 random graphs with up to 10
vertices, for \emph{every} subset of vertices, the subset is a vertex cover
exactly when the corresponding tests form a covering suite. Another compares
the exact solver against brute force on 200 random instances and checks that
greedy's output is always a valid cover within $H(d)\cdot\mathrm{OPT}$. These
are implementation checks rather than a substitute for the proofs.

\subsection{Experimental Evaluation}
\label{sec:p2-experiments}
\subsubsection{Experimental Setup}
Running time was measured on random instances with $m = n$ from 500 to
12{,}000, in two families. In the \emph{sparse} family each test checks about
20 requirements on average, so $N \approx 20m$. In the \emph{dense} family
each test checks each requirement with probability $p = 0.05$, so
$N \approx 0.05\,mn$. Every requirement is guaranteed to be checked by some
test. For each instance we ran 5 warm-up runs and report the median of 21
timed runs. All instances are generated from fixed seeds and are reproducible
exactly.

\subsubsection{Running Time}
The two families exercise different terms of the bound. In the sparse family
greedy needs many tests ($k \approx 0.087m$), so the $km$ scan dominates; in
the dense family $k$ grows slowly (from 38 to 74) and the $N$ term dominates.
Because the two terms do different kinds of work (a sequential scan versus
scattered counter updates), we fitted one constant per term,
\[
T(m,n,N) \approx a\cdot km + b\cdot (N + n),
\]
by non-negative least squares over both families, obtaining
$a = 0.186$~ns, $b = 3.07$~ns and $R^2 = 0.992$.

\subsubsection{Solution Quality}
To measure solution quality we compared greedy with the exact optimum, computed
by branch and bound, on 630 instances with $n = 60$ requirements,
$m \in \{10, 15, \dots, 40\}$ tests and densities $p \in \{0.05, 0.10, 0.20\}$
(30 instances per setting). Fig.~\ref{fig:quality} and
Table~\ref{tab:quality} summarize the results. Greedy found an optimal suite
in 61\% of the instances, used 4.9\% more tests than necessary on average, and
was never worse than 1.43 times the optimum, well inside the guarantee of
Theorem~\ref{thm:approx} ($H(d) \ge 2.28$ here). Greedy does worse when tests
overlap more (larger $p$) and when there are more tests to choose from, since
both create more opportunities for an early choice like the smoke test of
Section~\ref{sec:p2-example} to be misleading.

\subsubsection{Limitations and Validity}
The instances are random and synthetic, and each was timed in a single JVM
process. Real test suites have structured coverage, with groups of tests that
overlap heavily, so greedy's quality on them may differ from
Table~\ref{tab:quality}. The quality comparison is limited to small instances
because the exact solver takes exponential time. These measurements show how
the algorithm scales on the tested inputs; they do not prove the worst-case
bound, which comes from the analysis above.

\section{Conclusion}
Under the unit-slot assumptions, cloud task admission and placement is
capacitated bipartite matching. A polynomial-size maximum-flow network
preserves feasible assignments and their cardinalities, and an integral
maximum flow yields an optimal assignment. Dinic provides a complete
polynomial-time solution, including construction and extraction. The Java
experiments demonstrate reproducible behavior on the sampled synthetic
instances while leaving worst-case complexity as a mathematical guarantee.
Future experimental work should strengthen JVM replication and study
structured eligibility graphs and larger instances before drawing broader
performance conclusions.

Regression test-suite minimization is a set-covering problem in disguise. The
reduction from \VC{} shows that it is NP-complete even when every requirement is
checked by exactly two tests, so we do not expect an efficient exact algorithm.
The greedy rule of always running the test that checks the most unchecked
requirements runs in $O(km + N + n)$ time, which our experiments confirmed
($R^2 = 0.992$), and it is guaranteed to be within a factor $H(d)$ of optimal.
In practice it did much better than that guarantee: on 630 random instances it
was optimal 61\% of the time and never more than 1.43 times the optimum.
Natural extensions are tests with different running times (weighted set cover)
and keeping some redundancy so that minimization does not reduce the suite's
ability to find faults~\cite{rothermel1998}.

public final class CloudTaskBenchmark {
    enum Distribution { FIXED, UNIFORM, SKEWED }
    record Pair(int task, int server) {}
    record Instance(int n, int m, double p, Distribution distribution, int baseCapacity,
                    long seed, List<Pair> pairs, int[] capacities) {}
    record Sample(long construction, long dinic, long extraction, long total, long flow) {}
    static volatile long blackhole;

    static final class Edge {
        final int to, reverse;
        long residual;
        Edge(int to, int reverse, long residual) {
            this.to = to; this.reverse = reverse; this.residual = residual;
        }
    }

    static final class Network {
        final ArrayList<Edge>[] adj;
        final Edge[] assignmentEdges;
        final int source, sink;
        final int[] level, next, queue, pathVertex, pathEdge;
        final long[] bottleneck;
        @SuppressWarnings("unchecked")
        Network(Instance in) {
            int vertices = Math.addExact(Math.addExact(in.n, in.m), 2);
            source = vertices - 2; sink = vertices - 1;
            adj = (ArrayList<Edge>[]) new ArrayList<?>[vertices];
            for (int v = 0; v < vertices; v++) adj[v] = new ArrayList<>();
            assignmentEdges = new Edge[in.pairs.size()];
            level = new int[vertices]; next = new int[vertices]; queue = new int[vertices];
            pathVertex = new int[vertices]; pathEdge = new int[vertices];
            bottleneck = new long[vertices];
            for (int i = 0; i < in.n; i++) add(source, i, 1);
            for (int k = 0; k < in.pairs.size(); k++) {
                Pair pair = in.pairs.get(k);
                assignmentEdges[k] = add(pair.task, in.n + pair.server, 1);
            }
            for (int j = 0; j < in.m; j++) add(in.n + j, sink, in.capacities[j]);
        }
        Edge add(int u, int v, long capacity) {
            Edge forward = new Edge(v, adj[v].size(), capacity);
            Edge reverse = new Edge(u, adj[u].size(), 0);
            adj[u].add(forward); adj[v].add(reverse);
            return forward;
        }
        boolean bfs() {
            Arrays.fill(level, -1);
            int head = 0, tail = 0;
            queue[tail++] = source; level[source] = 0;
            while (head < tail) {
                int u = queue[head++];
                for (Edge e : adj[u]) if (e.residual > 0 && level[e.to] < 0) {
                    level[e.to] = level[u] + 1;
                    queue[tail++] = e.to;
                }
            }
            return level[sink] >= 0;
        }
        // Iterative equivalent of current-arc DFS: avoids JVM recursion depth limits.
        long send(long limit) {
            int depth = 0;
            pathVertex[0] = source; bottleneck[0] = limit;
            while (true) {
                int u = pathVertex[depth];
                if (u == sink) {
                    long amount = bottleneck[depth];
                    for (int d = 0; d < depth; d++) {
                        Edge e = adj[pathVertex[d]].get(pathEdge[d]);
                        e.residual -= amount;
                        adj[e.to].get(e.reverse).residual += amount;
                    }
                    return amount;
                }
                while (next[u] < adj[u].size()) {
                    Edge e = adj[u].get(next[u]);
                    if (e.residual > 0 && level[e.to] == level[u] + 1) break;
                    next[u]++;
                }
                if (next[u] == adj[u].size()) {
                    if (depth == 0) return 0;
                    depth--;
                    next[pathVertex[depth]]++;
                } else {
                    Edge e = adj[u].get(next[u]);
                    pathEdge[depth] = next[u];
                    pathVertex[depth + 1] = e.to;
                    bottleneck[depth + 1] = Math.min(bottleneck[depth], e.residual);
                    depth++;
                }
            }
        }
        long maxFlow(int n) {
            long flow = 0;
            while (bfs()) {
                Arrays.fill(next, 0);
                long pushed;
                while ((pushed = send(n)) != 0) flow += pushed;
            }
            return flow;
        }
        int[] extract(Instance in) {
            int[] assignment = new int[in.n];
            Arrays.fill(assignment, -1);
            for (int k = 0; k < assignmentEdges.length; k++) {
                if (assignmentEdges[k].residual == 0) {
                    Pair p = in.pairs.get(k);
                    if (assignment[p.task] != -1) throw new AssertionError("Duplicate task");
                    assignment[p.task] = p.server;
                }
            }
            return assignment;
        }
    }

    static Instance generate(int n, int m, double p, Distribution d, int c, long seed) {
        // Separate streams ensure identical eligibility for all capacity distributions.
        SplittableRandom eligibility = new SplittableRandom(seed);
        SplittableRandom capacity = new SplittableRandom(seed ^ 0x6A09E667F3BCC909L);
        ArrayList<Pair> pairs = new ArrayList<>();
        for (int i = 0; i < n; i++) for (int j = 0; j < m; j++)
            if (eligibility.nextDouble() < p) pairs.add(new Pair(i, j));
        int[] capacities = new int[m];
        for (int j = 0; j < m; j++) capacities[j] = switch (d) {
            case FIXED -> c;
            case UNIFORM -> capacity.nextInt(2 * c + 1);
            case SKEWED -> capacity.nextInt(10) == 0 ? 10 * c : 0;
        };
        return new Instance(n, m, p, d, c, seed, List.copyOf(pairs), capacities);
    }

    static Sample run(Instance in) {
        long start = System.nanoTime();
        Network network = new Network(in);
        long constructed = System.nanoTime();
        long flow = network.maxFlow(in.n);
        long solved = System.nanoTime();
        int[] assignment = network.extract(in);
        long extracted = System.nanoTime();
        validate(in, assignment, flow); // Outside all reported timing intervals.
        blackhole = blackhole ^ flow ^ Arrays.hashCode(assignment);
        return new Sample(constructed - start, solved - constructed,
                          extracted - solved, extracted - start, flow);
    }

    static void validate(Instance in, int[] assignment, long flow) {
        int[] loads = new int[in.m];
        boolean[] eligible = new boolean[in.n];
        for (Pair p : in.pairs) if (assignment[p.task] == p.server) eligible[p.task] = true;
        long count = 0;
        for (int i = 0; i < in.n; i++) if (assignment[i] != -1) {
            int j = assignment[i];
            if (j < 0 || j >= in.m || !eligible[i]) throw new AssertionError("Eligibility");
            loads[j]++; count++;
        }
        for (int j = 0; j < in.m; j++)
            if (loads[j] > in.capacities[j]) throw new AssertionError("Capacity");
        if (count != flow) throw new AssertionError("Flow/assignment mismatch");
    }

    // Independent exhaustive optimizer for tiny correctness tests only.
    static int brute(Instance in, int task, int[] loads) {
        if (task == in.n) return 0;
        int best = brute(in, task + 1, loads);
        for (Pair p : in.pairs) if (p.task == task && loads[p.server] < in.capacities[p.server]) {
            loads[p.server]++;
            best = Math.max(best, 1 + brute(in, task + 1, loads));
            loads[p.server]--;
        }
        return best;
    }
    static void selfTest() {
        Instance example = new Instance(5, 3, 7.0 / 15, Distribution.FIXED, 0, 0,
            List.of(new Pair(0,0), new Pair(0,1), new Pair(1,0), new Pair(2,1),

    }

    static long median(List<Sample> samples, int field) {
        long[] values = new long[samples.size()];

                case 0 -> s.construction; case 1 -> s.dinic;
                case 2 -> s.extraction; default -> s.total;
            };

        int mid = values.length / 2;

            : values[mid - 1] + (values[mid] - values[mid - 1]) / 2;
    }

package testmin.model;

import java.util.Arrays;

/**
 * One regression test and the set of requirements it covers.
 */
public final class TestCase {

    private final int id;
    private final int[] covers;

    /**
     * @param id     test id; must equal this test's index in its {@link Instance}
     * @param covers requirement ids covered by this test (duplicates are removed)
     * @throws IllegalArgumentException if {@code id} or any requirement id is negative
     */
    public TestCase(int id, int[] covers) {
        if (id < 0) {
            throw new IllegalArgumentException("Test id must be non-negative: " + id);
        }
        int[] sorted = covers.clone();
        Arrays.sort(sorted);
        if (sorted.length > 0 && sorted[0] < 0) {
            throw new IllegalArgumentException("Requirement ids must be non-negative: " + sorted[0]);
        }
        this.id = id;
        this.covers = dedupSorted(sorted);
    }

    private static int[] dedupSorted(int[] sorted) {
        if (sorted.length == 0) {
            return sorted;
        }
        int unique = 1;
        for (int i = 1; i < sorted.length; i++) {
            if (sorted[i] != sorted[unique - 1]) {
                sorted[unique++] = sorted[i];
            }
        }
        return unique == sorted.length ? sorted : Arrays.copyOf(sorted, unique);
    }

    public int id() {
        return id;
    }

    /** Number of distinct requirements this test covers. */
    public int size() {
        return covers.length;
    }

    /** The {@code i}-th covered requirement id (ascending order). Allocation-free access for hot loops. */
    public int requirement(int i) {
        return covers[i];
    }

    /** Defensive copy of the covered requirement ids, in ascending order. */
    public int[] covers() {
        return covers.clone();
    }

    /** Largest requirement id covered, or -1 if this test covers nothing. */
    public int maxRequirement() {
        return covers.length == 0 ? -1 : covers[covers.length - 1];
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof TestCase other && id == other.id && Arrays.equals(covers, other.covers);
    }

    @Override
    public int hashCode() {
        return 31 * Integer.hashCode(id) + Arrays.hashCode(covers);
    }

    @Override
    public String toString() {
        return "t" + id + Arrays.toString(covers);
    }

import java.util.List;

/**
 * An instance of Test-Suite Minimization: a universe of requirements
 * {@code U = {0, ..., n-1}} and a list of tests, each covering a subset of U.
 */
public final class Instance {

    private final int numRequirements;
    private final List<TestCase> tests;
    private final long totalCoverageSize;

    /**
     * @throws IllegalArgumentException if ids are inconsistent or a test covers
     *                                  a requirement outside {@code [0, numRequirements)}
     */
    public Instance(int numRequirements, List<TestCase> tests) {
        if (numRequirements < 0) {
            throw new IllegalArgumentException("numRequirements must be non-negative: " + numRequirements);
        }
        List<TestCase> copy = List.copyOf(tests); // also rejects null elements
        long total = 0;
        for (int i = 0; i < copy.size(); i++) {
            TestCase t = copy.get(i);
            if (t.id() != i) {
                throw new IllegalArgumentException("Test at index " + i + " has id " + t.id());
            }
            if (t.maxRequirement() >= numRequirements) {
                throw new IllegalArgumentException(
                        "Test " + i + " covers requirement " + t.maxRequirement()
                                + " but only " + numRequirements + " exist");
            }
            total += t.size();
        }
        this.numRequirements = numRequirements;
        this.tests = copy;
        this.totalCoverageSize = total;
    }

    /** n = |U|. */
    public int numRequirements() {
        return numRequirements;
    }

    /** m = number of tests. */
    public int numTests() {
        return tests.size();
    }

    public TestCase test(int id) {
        return tests.get(id);
    }

    /** Unmodifiable view of all tests. */
    public List<TestCase> tests() {
        return tests;
    }

    /** N = sum of |S_i| over all tests: the input size that drives running time. */
    public long totalCoverageSize() {
        return totalCoverageSize;
    }

    /** True iff every requirement is covered by at least one test (i.e. some solution exists). */
    public boolean isFeasible() {
        boolean[] covered = new boolean[numRequirements];
        int remaining = numRequirements;
        for (TestCase t : tests) {
            for (int i = 0; i < t.size(); i++) {
                int r = t.requirement(i);
                if (!covered[r]) {
                    covered[r] = true;
                    remaining--;
                }
            }
        }
        return remaining == 0;
    }

package testmin.algo;

import testmin.model.Instance;
import testmin.model.TestCase;

/**
 * Inverted index: for each requirement r, the ids of the tests that cover r.
 */
final class CoverageIndex {

    private CoverageIndex() {
    }

    /** {@code result[r]} lists the ids of tests covering requirement r, in ascending order. */
    static int[][] build(Instance instance) {
        int n = instance.numRequirements();
        int[] counts = new int[n];
        for (TestCase t : instance.tests()) {
            for (int i = 0; i < t.size(); i++) {
                counts[t.requirement(i)]++;
            }
        }
        int[][] coveredBy = new int[n][];
        for (int r = 0; r < n; r++) {
            coveredBy[r] = new int[counts[r]];
        }
        int[] fill = new int[n];
        for (TestCase t : instance.tests()) {
            for (int i = 0; i < t.size(); i++) {
                int r = t.requirement(i);
                coveredBy[r][fill[r]++] = t.id();
            }
        }
        return coveredBy;
    }
}

package testmin.algo;

import java.util.ArrayList;
import java.util.List;
import testmin.model.InfeasibleInstanceException;
import testmin.model.Instance;
import testmin.model.Solution;
import testmin.model.TestCase;

/**
 * Greedy test-suite minimization: repeatedly select the test that covers the
 * most still-uncovered requirements (ties broken by smallest id).
 */
public final class GreedyMinimizer implements Minimizer {

    @Override
    public Solution solve(Instance instance) {
        int m = instance.numTests();
        int n = instance.numRequirements();
        int[][] coveredBy = CoverageIndex.build(instance);

        // gain[t] = number of requirements covered by t that are not yet covered.
        int[] gain = new int[m];
        for (int t = 0; t < m; t++) {
            gain[t] = instance.test(t).size();
        }

        boolean[] covered = new boolean[n];
        int remaining = n;
        List<Integer> selected = new ArrayList<>();

        while (remaining > 0) {
            int best = argMax(gain);
            if (best < 0 || gain[best] == 0) {
                throw new InfeasibleInstanceException(
                        remaining + " requirement(s) are not covered by any test");
            }
            selected.add(best);

            TestCase chosen = instance.test(best);
            for (int i = 0; i < chosen.size(); i++) {
                int r = chosen.requirement(i);
                if (!covered[r]) {
                    covered[r] = true;
                    remaining--;
                    for (int t : coveredBy[r]) {
                        gain[t]--;
                    }
                }
            }
        }
        return new Solution(selected);
    }

    /** Index of the largest value (first one on ties), or -1 for an empty array. */
    private static int argMax(int[] values) {
        int best = -1;
        int bestValue = Integer.MIN_VALUE;
        for (int i = 0; i < values.length; i++) {
            if (values[i] > bestValue) {
                bestValue = values[i];
                best = i;
            }
        }
        return best;
    }

    @Override
    public String name() {
        return "greedy";
    }
}

package testmin.algo;

import java.util.ArrayList;
import java.util.List;
import testmin.model.InfeasibleInstanceException;
import testmin.model.Instance;
import testmin.model.Solution;
import testmin.model.TestCase;

/**
 * Exact (optimal) test-suite minimization by branch and bound.
 */
public final class ExactMinimizer implements Minimizer {

    @Override
    public Solution solve(Instance instance) {
        if (!instance.isFeasible()) {
            throw new InfeasibleInstanceException("Some requirement is not covered by any test");
        }
        List<Integer> upperBound = new GreedyMinimizer().solve(instance).selectedTestIds();
        Search search = new Search(instance, upperBound);
        search.run(0);
        return new Solution(search.best);
    }

    @Override
    public String name() {
        return "exact";
    }

    /** Mutable state for one branch-and-bound run. */
    private static final class Search {
        private final Instance instance;
        private final int[][] coveredBy;
        private final int[] coverCount; // how many selected tests cover each requirement
        private final List<Integer> current = new ArrayList<>();
        private int uncovered;
        private List<Integer> best;

        Search(Instance instance, List<Integer> initialBest) {
            this.instance = instance;
            this.coveredBy = CoverageIndex.build(instance);
            this.coverCount = new int[instance.numRequirements()];
            this.uncovered = instance.numRequirements();
            this.best = new ArrayList<>(initialBest);
        }

        /** Invariant: every requirement below {@code firstCandidate} is covered. */
        void run(int firstCandidate) {
            if (uncovered == 0) {
                if (current.size() < best.size()) {
                    best = new ArrayList<>(current);
                }
                return;
            }
            // At least one more test is needed, so only continue if that could beat the best.
            if (current.size() + 1 >= best.size()) {
                return;
            }
            int r = firstCandidate;
            while (coverCount[r] > 0) {
                r++;
            }
            for (int t : coveredBy[r]) {
                add(t);
                current.add(t);
                run(r + 1);
                current.remove(current.size() - 1);
                remove(t);
            }
        }

        private void add(int testId) {
            TestCase t = instance.test(testId);
            for (int i = 0; i < t.size(); i++) {
                if (coverCount[t.requirement(i)]++ == 0) {
                    uncovered--;
                }
            }
        }

        private void remove(int testId) {
            TestCase t = instance.test(testId);
            for (int i = 0; i < t.size(); i++) {
                if (--coverCount[t.requirement(i)] == 0) {
                    uncovered++;
                }
            }
        }
    }
}

package testmin.reduction;

import java.util.ArrayList;
import java.util.List;

/**
 * Simple undirected graph with vertices {@code 0..numVertices-1} and an
 * indexed list of edges. Immutable. Self-loops are rejected.
 */
public final class Graph {

    /** An undirected edge {u, v}. */
    public record Edge(int u, int v) {
    }

    private final int numVertices;
    private final List<Edge> edges;

    public Graph(int numVertices, List<Edge> edges) {
        if (numVertices < 0) {
            throw new IllegalArgumentException("numVertices must be non-negative");
        }
        for (Edge e : edges) {
            if (e.u() < 0 || e.u() >= numVertices || e.v() < 0 || e.v() >= numVertices) {
                throw new IllegalArgumentException("Edge endpoint out of range: " + e);
            }
            if (e.u() == e.v()) {
                throw new IllegalArgumentException("Self-loops are not allowed: " + e);
            }
        }
        this.numVertices = numVertices;
        this.edges = List.copyOf(edges);
    }

    public int numVertices() {
        return numVertices;
    }

    public List<Edge> edges() {
        return edges;
    }

    /** True iff every edge has at least one endpoint in {@code vertices}. */
    public boolean isVertexCover(List<Integer> vertices) {
        boolean[] in = new boolean[numVertices];
        for (int v : vertices) {
            in[v] = true;
        }
        for (Edge e : edges) {
            if (!in[e.u()] && !in[e.v()]) {
                return false;
            }
        }
        return true;
    }

    /** Builds a graph from a list of {u, v} pairs. Convenience for tests. */
    public static Graph of(int numVertices, int[][] pairs) {
        List<Edge> list = new ArrayList<>(pairs.length);
        for (int[] p : pairs) {
            list.add(new Edge(p[0], p[1]));
        }
        return new Graph(numVertices, list);
    }
}

    public static Instance reduce(Graph graph) {

            tests.add(new TestCase(v, covers));

package testmin.gen;

import java.util.ArrayList;
import java.util.List;
import java.util.Random;
import testmin.model.Instance;
import testmin.model.TestCase;

/**
 * Seeded random generator of feasible instances.
 */
public final class InstanceGenerator {

    private final Random random;

    public InstanceGenerator(long seed) {
        this.random = new Random(seed);
    }

    public Instance generate(int numTests, int numRequirements, double density) {
        if (numTests < 1 && numRequirements > 0) {
            throw new IllegalArgumentException("Need at least one test to cover requirements");
        }
        if (density < 0.0 || density > 1.0) {
            throw new IllegalArgumentException("density must be in [0, 1]: " + density);
        }

        List<List<Integer>> covers = new ArrayList<>(numTests);
        for (int t = 0; t < numTests; t++) {
            covers.add(sampleRequirements(numRequirements, density));
        }

        boolean[] covered = new boolean[numRequirements];
        for (List<Integer> c : covers) {
            for (int r : c) {
                covered[r] = true;
            }
        }
        for (int r = 0; r < numRequirements; r++) {
            if (!covered[r]) {
                covers.get(random.nextInt(numTests)).add(r);
            }
        }

        List<TestCase> tests = new ArrayList<>(numTests);
        for (int t = 0; t < numTests; t++) {
            tests.add(new TestCase(t, covers.get(t).stream().mapToInt(Integer::intValue).toArray()));
        }
        return new Instance(numRequirements, tests);
    }

    /**
     * Bernoulli(p) sampling of {0..n-1} using geometric skips, so the cost is
     * proportional to the number of items chosen rather than to n.
     */
    private List<Integer> sampleRequirements(int n, double p) {
        List<Integer> chosen = new ArrayList<>();
        if (p <= 0.0) {
            return chosen;
        }
        if (p >= 1.0) {
            for (int r = 0; r < n; r++) {
                chosen.add(r);
            }
            return chosen;
        }
        double logQ = Math.log(1.0 - p);
        long r = -1;
        while (true) {
            double u = 1.0 - random.nextDouble(); // in (0, 1]
            r += 1 + (long) Math.floor(Math.log(u) / logQ);
            if (r >= n) {
                return chosen;
            }
            chosen.add((int) r);
        }
    }
}

        this.columns = header.length;
        writeRow((Object[]) header);
    }

    void writeRow(Object... values) throws IOException {
        if (values.length != columns) {
            throw new IllegalArgumentException("Expected " + columns + " values, got " + values.length);
        }
        StringJoiner line = new StringJoiner(",");
        for (Object v : values) {
            line.add(String.valueOf(v));
        }
        out.write(line.toString());
        out.newLine();
    }

    @Override
    public void close() throws IOException {
        out.close();
    }
}

package testmin.bench;

import java.io.IOException;
import java.nio.file.Path;
import java.util.Arrays;
import testmin.algo.GreedyMinimizer;
import testmin.algo.Minimizer;
import testmin.gen.InstanceGenerator;
import testmin.model.Instance;
import testmin.model.Solution;
import testmin.verify.CoverageVerifier;

/**
 * Measures greedy running time against the predicted cost k*m + N + n.
 */
public final class RuntimeBenchmark {

    private static final int[] SIZES = {500, 1000, 2000, 3000, 4000, 6000, 8000, 10000, 12000};
    private static final double SPARSE_AVG_TEST_SIZE = 20.0;
    private static final double DENSE_DENSITY = 0.05;
    private static final int WARMUP_RUNS = 5;
    private static final int REPETITIONS = 21;
    private static final long SEED = 42L;

    private RuntimeBenchmark() {
    }

    public static void main(String[] args) throws IOException {
        Path outDir = Path.of(args.length > 0 ? args[0] : "results");
        Minimizer greedy = new GreedyMinimizer();
        InstanceGenerator generator = new InstanceGenerator(SEED);

        try (CsvWriter csv = new CsvWriter(outDir.resolve("runtime.csv"),
                "family", "m", "n", "N", "k", "predicted_ops", "median_ns")) {
            for (String family : new String[] {"sparse", "dense"}) {
                for (int size : SIZES) {
                    double density = family.equals("sparse")
                            ? Math.min(1.0, SPARSE_AVG_TEST_SIZE / size)
                            : DENSE_DENSITY;
                    Instance inst = generator.generate(size, size, density);
                    Solution sol = greedy.solve(inst);
                    if (!CoverageVerifier.coversAll(inst, sol)) {
                        throw new IllegalStateException("Greedy produced an invalid cover");
                    }
                    long median = medianNanos(greedy, inst);
                    long k = sol.size();
                    long predicted = k * inst.numTests() + inst.totalCoverageSize() + inst.numRequirements();

                    csv.writeRow(family, inst.numTests(), inst.numRequirements(),
                            inst.totalCoverageSize(), k, predicted, median);
                    System.out.printf("%-6s m=n=%-6d N=%-9d k=%-5d pred=%-11d time=%.3f ms%n",
                            family, size, inst.totalCoverageSize(), k, predicted, median / 1e6);
                }
            }
        }
    }

    private static long medianNanos(Minimizer minimizer, Instance inst) {
        for (int i = 0; i < WARMUP_RUNS; i++) {
            minimizer.solve(inst);
        }
        long[] times = new long[REPETITIONS];
        for (int i = 0; i < REPETITIONS; i++) {
            long start = System.nanoTime();
            minimizer.solve(inst);
            times[i] = System.nanoTime() - start;
        }
        Arrays.sort(times);
        return times[REPETITIONS / 2];
    }
}

package testmin.bench;

import java.io.IOException;
import java.nio.file.Path;
import testmin.algo.ExactMinimizer;
import testmin.algo.GreedyMinimizer;
import testmin.gen.InstanceGenerator;
import testmin.model.Instance;
import testmin.model.TestCase;

/**
 * Compares the greedy solution size to the optimum (from {@link ExactMinimizer})
 * on small random instances, together with the theoretical bound H(d).
 */
public final class QualityBenchmark {

    private static final int[] NUM_TESTS = {10, 15, 20, 25, 30, 35, 40};
    private static final int NUM_REQUIREMENTS = 60;
    private static final double[] DENSITIES = {0.05, 0.10, 0.20};
    private static final int TRIALS_PER_SETTING = 30;
    private static final long SEED = 7L;

    private QualityBenchmark() {
    }

    public static void main(String[] args) throws IOException {
        Path outDir = Path.of(args.length > 0 ? args[0] : "results");
        GreedyMinimizer greedy = new GreedyMinimizer();
        ExactMinimizer exact = new ExactMinimizer();
        InstanceGenerator generator = new InstanceGenerator(SEED);

        try (CsvWriter csv = new CsvWriter(outDir.resolve("quality.csv"),
                "m", "n", "density", "trial", "greedy", "optimal", "ratio", "harmonic_bound")) {
            for (double density : DENSITIES) {
                for (int m : NUM_TESTS) {
                    int worse = 0;
                    for (int trial = 0; trial < TRIALS_PER_SETTING; trial++) {
                        Instance inst = generator.generate(m, NUM_REQUIREMENTS, density);
                        int g = greedy.solve(inst).size();
                        int opt = exact.solve(inst).size();
                        if (g > opt) {
                            worse++;
                        }
                        csv.writeRow(m, NUM_REQUIREMENTS, density, trial, g, opt,
                                String.format("%.4f", (double) g / opt),
                                String.format("%.4f", harmonic(maxTestSize(inst))));
                    }
                    System.out.printf("density=%.2f m=%-3d greedy worse than optimal in %d/%d trials%n",
                            density, m, worse, TRIALS_PER_SETTING);
                }
            }
        }
    }

    private static int maxTestSize(Instance inst) {
        int max = 0;
        for (TestCase t : inst.tests()) {
            max = Math.max(max, t.size());
        }
        return max;
    }

    /** H(d) = 1 + 1/2 + ... + 1/d. */
    static double harmonic(int d) {
        double h = 0.0;
        for (int i = 1; i <= d; i++) {
            h += 1.0 / i;
        }
        return h;
    }
}

"""Make the report figures from the benchmark CSVs.

Reads results/runtime.csv and results/quality.csv and writes
figures/runtime.png, figures/ratio.png and figures/quality.png.

Runtime model: time ~= a*(k*m) + b*(N + n), with a and b fitted by
non-negative least squares.

Usage: python3 scripts/plot.py
"""
import csv
from pathlib import Path

import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt  # noqa: E402
import numpy as np  # noqa: E402
from scipy.optimize import nnls  # noqa: E402

RESULTS = Path("results")
FIGURES = Path("figures")
COLORS = {"sparse": "#1f3f99", "dense": "#c2410c", 0.05: "#1f3f99", 0.1: "#c2410c", 0.2: "#047857"}

plt.rcParams.update({"font.family": "serif", "font.size": 8})


def read(name):
    with open(RESULTS / name, newline="") as f:
        return list(csv.DictReader(f))


def save(fig, name):
    fig.tight_layout()
    fig.savefig(FIGURES / name, dpi=300)
    plt.close(fig)


def runtime_figures():
    rows = read("runtime.csv")
    family = np.array([r["family"] for r in rows])
    m = np.array([int(r["m"]) for r in rows])
    km = np.array([int(r["k"]) * int(r["m"]) for r in rows], dtype=float)
    nn = np.array([int(r["N"]) + int(r["n"]) for r in rows], dtype=float)
    ms = np.array([int(r["median_ns"]) for r in rows]) / 1e6

    (a, b), _ = nnls(np.column_stack([km, nn]), ms)
    model = a * km + b * nn
    r2 = 1 - np.sum((ms - model) ** 2) / np.sum((ms - ms.mean()) ** 2)
    print(f"a = {a * 1e6:.3f} ns, b = {b * 1e6:.3f} ns, R^2 = {r2:.4f}")

    fig, ax = plt.subplots(figsize=(3.5, 2.5))
    for fam in ("sparse", "dense"):
        s = family == fam
        ax.plot(m[s], ms[s], "o", color=COLORS[fam], markersize=3.5, label=f"{fam}, measured")
        ax.plot(m[s], model[s], "--", color=COLORS[fam], linewidth=1, label=f"{fam}, model")
    ax.set_xlabel("Number of tests $m$ (= number of requirements $n$)")
    ax.set_ylabel("Median running time (ms)")
    ax.grid(color="0.9")
    ax.legend(fontsize=6.5, frameon=False)
    save(fig, "runtime.png")

    fig, ax = plt.subplots(figsize=(3.5, 2.3))
    for fam in ("sparse", "dense"):
        s = family == fam
        ax.plot(m[s], ms[s] / model[s], "o-", color=COLORS[fam], markersize=3.5, linewidth=1, label=fam)
    ax.axhline(1.0, color="0.4", linestyle=":", linewidth=1)
    ax.set_xlabel("Number of tests $m$ (= number of requirements $n$)")
    ax.set_ylabel("Measured / model")
    ax.set_ylim(0, 2)
    ax.grid(color="0.9")
    ax.legend(fontsize=6.5, frameon=False)
    save(fig, "ratio.png")


def quality_figure():
    rows = read("quality.csv")
    ratios = {}
    for r in rows:
        ratios.setdefault((float(r["density"]), int(r["m"])), []).append(float(r["ratio"]))

    fig, ax = plt.subplots(figsize=(3.5, 2.5))
    for p in sorted({p for p, _ in ratios}):
        m = sorted(mm for pp, mm in ratios if pp == p)
        ax.plot(m, [np.mean(ratios[(p, x)]) for x in m], "o-", color=COLORS[p],
                markersize=3.5, linewidth=1, label=f"$p={p:g}$, mean")
        ax.plot(m, [np.max(ratios[(p, x)]) for x in m], "^--", color=COLORS[p],
                markersize=3, linewidth=0.8, alpha=0.7, label=f"$p={p:g}$, worst")
    ax.axhline(1.0, color="0.4", linestyle=":", linewidth=1)
    ax.set_xlabel("Number of tests $m$ ($n = 60$ requirements)")
    ax.set_ylabel("Greedy size / optimal size")
    ax.grid(color="0.9")
    ax.legend(fontsize=6, frameon=False, ncol=2, loc="upper left")
    save(fig, "quality.png")


if __name__ == "__main__":
    FIGURES.mkdir(exist_ok=True)
    runtime_figures()
    quality_figure()
    print("Saved figures/runtime.png, figures/ratio.png, figures/quality.png")
